# 0001 — v0.1 foundation: stack, layout, open items

- Status: Accepted
- Date: 2026-10-04

## Context

The master prompt fixes the stack (WXT, React, Tailwind, Zustand, Zod, idb, Vitest, Playwright,
pnpm). Some current package versions needed choices the docs do not cover.

## Decision

- **TypeScript 6.0**, not 7.0: `typescript-eslint` 8.x supports `<6.1`. Revisit when it supports 7.
- **React 19**, **Tailwind 4** (CSS-first config with design tokens in
  `src/entrypoints/sidepanel/style.css`), **Zod 4**, **Vitest 5**, **ESLint 10** flat config.
- **Zod runs in `jitless` mode** in every entrypoint (`src/netsuite/zodSetup.ts`). Zod 4 otherwise
  compiles validators with `new Function` when the page CSP allows it, which would break the
  "no eval" rule inside the MAIN-world bridge.
- **Single package** for v0.1 (allowed by docs/architecture.md §8). `src/netsuite` uses no
  extension APIs; browser APIs (`DOMParser`, `fetch`) are passed in or isolated in
  `adapter/contentService.ts`, so the folder can move to `packages/core`.
- **No auto-imports** in WXT (`imports: false`): explicit imports keep files greppable.
- **Fixture data is compiled out of production builds** through the build-time constant
  `__LOUPE_FIXTURES__` (see `wxt.config.ts`). `pnpm build:e2e` / `pnpm dev:fixtures` default the
  side panel to `FixtureAdapter`.
- ESLint enforces: no `eval`/`new Function`, no `innerHTML`/`dangerouslySetInnerHTML`, no `fetch`
  in UI code (`src/features`, `src/shared`, side panel), named exports outside entrypoints.

## Open items (need a decision or a real account)

1. **License** (docs/architecture.md §9: MIT vs GPL-3.0 vs AGPL-3.0) — not chosen; no `LICENSE`
   file yet. Needed before the repository goes public.
2. **Repository URL** in `src/shared/constants.ts` is a placeholder.
3. **Security contact email** for `SECURITY.md`.
4. **VERIFY items** — every assumption about NetSuite is tagged `VERIFY` in code:
   - URL → record type table (`context/recordTypeMap.ts`), release preview host suffix
     (`context/environment.ts`), search/list paths (`context/detect.ts`);
   - form DOM: `<fieldid>_fs_lbl` labels, `uir-required-icon`, hidden `baserecordtype`/`id`
     inputs (`parsers/formDom.ts`);
   - record XML shape and `xml=T` behaviour in edit mode (`parsers/recordXml.ts`);
   - AMD `require` errback, `N/currentRecord` Field properties, `runSuiteQL.promise`,
     SuiteScript 1.0 globals (`bridge/handler.ts`);
   - SuiteQL tables/columns and stored value formats (`queries/automation.ts`), error texts
     (`errors.ts`);
   - script/deployment/file/workflow page paths (`urls.ts`).
   Use the P-0.1b prompt (`prompts/phase-prompts.md`) to produce the sandbox checklist.

## Consequences

Upgrading TypeScript to 7 and removing `jitless` are separate, deliberate changes.

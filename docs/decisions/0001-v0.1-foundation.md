# 0001 — v0.1 foundation: stack, layout, open items

- Status: Accepted
- Date: 2026-10-04

## Context

The master prompt fixes the stack (WXT, React, Tailwind, Zustand, Zod, idb, Vitest, Playwright,
pnpm). Some current package versions needed choices the docs do not cover.

## Decision

- **TypeScript 6.0**, not 7.0: `typescript-eslint` 8.x supports `<6.1`. Revisit when it supports 7.
- **React 19**, **Tailwind 4** (CSS-first config with design tokens in
  `src/entrypoints/sidepanel/style.css`), **Zod 4**, **Vitest 5**, **ESLint 10** flat config.
- **Zod runs in `jitless` mode** in every entrypoint (`src/netsuite/zodSetup.ts`). Zod 4 otherwise
  compiles validators with `new Function` when the page CSP allows it, which would break the
  "no eval" rule inside the MAIN-world bridge.
- **Single package** for v0.1 (allowed by docs/architecture.md §8). `src/netsuite` uses no
  extension APIs; browser APIs (`DOMParser`, `fetch`) are passed in or isolated in
  `adapter/contentService.ts`, so the folder can move to `packages/core`.
- **No auto-imports** in WXT (`imports: false`): explicit imports keep files greppable.
- **Fixture data is compiled out of production builds** through the build-time constant
  `__LOUPE_FIXTURES__` (see `wxt.config.ts`). `pnpm build:e2e` / `pnpm dev:fixtures` default the
  side panel to `FixtureAdapter`.
- ESLint enforces: no `eval`/`new Function`, no `innerHTML`/`dangerouslySetInnerHTML`, no `fetch`
  in UI code (`src/features`, `src/shared`, side panel), named exports outside entrypoints.

     (`errors.ts`);

   Use the P-0.1b prompt (`prompts/phase-prompts.md`) to produce the sandbox checklist.

## Sandbox check, 2026-10-04 (one sandbox account, purchase order in view mode)

Confirmed:

- Host `<account>-sb1.app.netsuite.com` is detected as sandbox; banner and pill are correct.
- `purchord.nl` maps to `purchaseorder`; the record ID is read from the URL.
- `xml=T` returns the record XML (191 body fields on the test record).
- `<fieldid>_fs_lbl` labels work on the Redwood theme; badges attach to them.
- AMD `require` and `N/query.runSuiteQL` work from the bridge; the `scriptdeployment` + `script`
  query (full variant, including `loglevel`, `executioncontext`, `BUILTIN.DF(scriptfile)`) and
  the record-type match work.
- `workflow` columns: `internalid` (no `id`), `scriptid`, `name`, `recordtype`, `recordtypes`,
  `releasestatus`, `isinactive`, `inittriggertype`, `initoncreate`, `initonvieworupdate`,
  `description`, `owner`, `runasadmin`, `islogenabled`, and others.
- `N/currentRecord.get()` works in view mode but reports the rendered type (`text` for `entity`).

Found and fixed:

- The record XML contains `_csrf` and `_eml_nkey_`; they were shown in the Field Explorer.
  Token fields are now dropped everywhere (`parsers/sensitiveFields.ts`).
- The workflow query used `w.id`; it now uses `w.internalid`.
- Field ID badges inherited `text-transform: uppercase` from Redwood labels.
- Deployments set to all contexts list ~36 context names; the card now says "All contexts".
- Hidden/system fields crowded the list; they are now folded under "Not on this form".
- View mode had no field types; they now come from a read-only `N/record.load`.

Still to check: the workflow fix and `N/record.load` in the same account, the
`recordtype`/`recordtypes` value format, edit mode, customer and custom records, a production
account, Release Preview, favicon tint, and the Script/Deployment/File/Workflow links.

## Consequences

Upgrading TypeScript to 7 and removing `jitless` are separate, deliberate changes.
